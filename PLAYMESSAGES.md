# PlayMessages

Open `http://127.0.0.1:4173/#messages` to play immediately in Grace, the browser inside Kairos World. A persistent guest profile is created locally; no sign-in is required in public preview mode. Grace's navigation links to the story collection. See `GRACE_WORLD.md` for the current world entry and map.

Ten original contemporary stories are each based on a different David Antwi / Kharis Church message. The full source catalogue, verified through [API Anything](https://github.com/goodnight000/api-anything), is in `public/playmessages/sources.json`. `scripts/research-playmessages.mts` refreshes public metadata without vidIQ calls. It uses a local, ignored checkout in `.tools/api-anything` with its dependencies installed; run using that checkout's tsx CLI with `API_ANYTHING_LOCAL_ONLY=1`. Keep its read-only maximum tier at 1. YouTube's channel-list selector drifted, while all ten getVideo reads succeeded. API Anything's own YouTube specification does not currently expose transcription; see its `docs/research/youtube-captions.md`. English captions retrieved earlier in the session were reused; no additional vidIQ requests were made after the user asked to avoid credits.

Each story has a different lead and supporting cast, three chapters, three original scene illustrations, six decisions and three authored conclusions. In every chapter, players first speak with a character (listen or share a concern) and inspect a scene-specific object. Sixty distinct conversations/object discoveries are authored across the collection. Evidence and the conversation approach persist in the journal and inform the follow-up dialogue. In each chapter, the response changes dialogue, consequences and the follow-through action. The following chapter remembers the previous consequence. All 216 combinations of response and follow-through choices per story terminate and restore deterministically. Scene transitions are illustrated visual-novel scenes, not a 3D free-roaming RPG or newly animated videos. Actual sermon snippets play through the official privacy-enhanced YouTube embed.

Every chapter has a 75-second source excerpt at a selected timestamp, matching local caption cues, a source link and a relevant KJV reading. Videos begin automatically when the story reaches a cutscene. The official YouTube IFrame API handles playback/end events. If sound is blocked, a muted autoplay attempt and explicit Play / enable sound control provide recovery. The YouTube surface is non-interactive: controls, seeking and keyboard shortcuts are disabled, and pointer input is blocked. Playback advances to the next story interaction automatically at the configured end. Captions and a transcript remain available; an error-only continuation prevents an unavailable video from blocking the game. YouTube controls availability, advertisements, related videos and captions. Pause, hiding the tab, route changes and module disposal stop the embed; returning offers the play button again.

Full English automatic captions are in `public/playmessages/transcripts/`, published after the user confirmed permission on 8 November 2026. They are labelled automatic and may contain errors; they are not claimed to be professionally corrected transcripts. Game dialogue, summaries and choices are original fiction informed by the messages, clearly distinguished from sermon quotations and Scripture. No secret or paid API credential is used in the browser. Captions, source metadata and scenes are bundled local assets; viewing a video needs an internet connection.

The per-player `kairos-playmessages-v1:<player-id>` save contains validated transition events, discovered endings and best Grace rewards. Loading replays events through the rules, rejects invalid saves and never trusts a saved score. A replay retains endings and the highest reward, rather than farming duplicate currency. Grace is a progress reward, not a measure of salvation or divine favour. A failed storage write gives an explicit visit-only notice and an in-memory fallback. These story saves are device-local, including for family players; the existing Supabase family dashboard continues tracking the sixteen Bible games. There are no new backend credentials or migrations.

The chapter journal records original dialogue, selected responses and follow-through. Touch, mouse and keyboard are supported: number keys choose, Enter continues when the scene is focused, Escape pauses. Dialogs use native focus trapping. Text is actual HTML, never baked into scene artwork. Scene fades respect reduced motion. Colour-mode-independent dialogue panels and save notices provide explicit text/background pairs.

Artwork provenance and scene briefs are in `public/playmessages/art-provenance.json`. Thirty scenes are stored in ten three-panel WebP atlases, approximately 3.8 MB in total instead of 27 MB of PNGs. `scripts/low-poly-icons.mjs` reproduces all sixteen original faceted SVG game icons. Existing supplied artwork and licence files are retained. Large art and transcript folders use static assets and are excluded from the initial offline precache and Worker bundle, with platform-neutral path checks. They are cached on first use. Content/engine/UI code is small and precached normally.

The November Bible banks add 32 original questions, 10 acting/drawing prompts, four word-search sets and four story sequences. Existing per-player shuffle bags rotate these with the previous banks and avoid recent repeats. All new entries reference Scripture.

Verification: `node --test *.test.mjs` and `node scripts/build.mjs`; local browser checks cover all sixteen game launches and pause/resume, story choices, cutscene playback at its selected timestamp, full transcripts, completed-story resume and responsive layouts. Tests in `playmessages.test.mjs` cover every route, three conclusions per story, clip bounds/cues, assets, corrupt saves, storage denial, player isolation and repeat rewards.
